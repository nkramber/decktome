## Findings

### P1-1: A session can erase the ledger and restart the budget

Status: open.

Open at: `998057fbf07a498c4a43b828193229a856dcc28f`.

File: `go/internal/livespend/livespend.go:80-86`.

Trigger: a live-eval session deletes or truncates its writable `bundle/spend.jsonl` after a paid run reaches the budget, then starts another paid command.

Expected: D-1169 requires a paid command to refuse a run after spend reaches the budget. D-1170 makes the session log the source because a session can edit the bundle.

Actual: `Start` calls `SumFile` on the bundle file alone. `SumFile` treats a missing file as zero spend. The wrapper sums protected logs after the session ends.

Consequence: the next paid command starts with an empty budget ledger. This action can let a session spend beyond the stated cap.

Correction: check each start against state that the session cannot lower, or block session edits to the ledger used by `Start`.

Regression check: spend the budget, remove or truncate the bundle file, and prove that the next `Start` refuses. Also prove that a normal next run below the cap still starts.
