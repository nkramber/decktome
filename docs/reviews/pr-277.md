## Findings

### P2-1: The request cap is independent on each API instance

Status: accepted risk, D-1106.

Open at: `a5583dfed06afdab3e0e7358132faa1889cd8505`.

File: `go/internal/agentsvc/fetch.go:47-50` at the earlier head.

Trigger: one user sends requests that Cloud Run routes to more than one API instance within a minute.

Expected: D-1100 first limited each user to 10 reads per minute.

Actual: `Server.New` creates an in-memory limiter for each process. D-1106 amends the contract to limit each user to 10 reads per minute on each API instance.

Consequence: this behavior is now the owner's accepted contract. It permits up to 30 reads per minute when Cloud Run uses three instances.

Correction: none. The owner chose the per-instance cap in D-1106.

Regression check: `go test -race ./internal/agentsvc` passed. `TestFetchDeckListLimitsEachUser` checks the per-instance cap.

### P2-2: An import can claim a deck that it never read

Status: fixed in `8ec32db`.

Open at: `a5583dfed06afdab3e0e7358132faa1889cd8505`.

File: `go/internal/agentsvc/fetch.go` and `go/internal/agentsvc/import.go` at the earlier head.

Trigger: an authenticated client calls `ImportDeck` with an Archidekt link and unrelated list text, without a prior fetch.

Expected: D-1107 requires a server read of the same deck and text by the same user before the import can keep the link.

Actual: `FetchDeckList` records the deck id and text hash for the user. `ImportDeck` checks that record and fails closed when the record is absent, expired, mismatched, or unavailable.

Consequence: an imported deck cannot claim a source that the server did not read for that user.

Correction: the owner added the read record in `go/internal/deckreads` and wired it to the API. No further correction remains.

Regression check: `go test -race ./internal/agentsvc ./internal/deckreads` passed. `TestImportKeepsOnlyTheRemadeLink`, `TestAReadLogFaultFailsClosed`, and `TestMatchesNeedsTheDeckAndTheText` cover the trigger and boundaries. The emulator round-trip passed in CI.

### P2-3: A valid read expires after twenty newer reads

Status: open.

Open at: `8d9737c0468336f8587dc83c34223ccf12a2c777`.

File: `go/internal/deckreads/deckreads.go:61-63`.

Trigger: a user reads 21 different decks within one hour, then imports the first list.

Expected: D-1107 and the PR-121 gate keep each read eligible for one hour.

Actual: `Keep` drops every entry but the newest 20. `Has` then rejects the first deck even though its read is less than one hour old.

Consequence: a user can read a link successfully, but the app rejects its unchanged list during import.

Correction: keep each unexpired read within the supported request limit, and test more than 20 reads before the first import.

Regression check: add a case that proves read 1 still matches after 20 newer reads. Run `go test ./internal/deckreads ./internal/agentsvc`.

### P2-4: Expired read hashes stay in Firestore

Status: open.

Open at: `8d9737c0468336f8587dc83c34223ccf12a2c777`.

File: `go/internal/deckreads/deckreads.go:87-104`.

Trigger: a user reads one deck and makes no later deck-link read.

Expected: D-1107 and the PR-121 gate keep each read for one hour.

Actual: `Has` ignores an expired read in memory, but it never deletes the Firestore document. `Add` prunes old entries only when a later read occurs.

Consequence: the user's deck id and text hash remain stored after the one-hour retention period.

Correction: expire the stored record after its newest read, or run a cleanup that removes expired records.

Regression check: run `make store-check`. Verify that an expired record no longer exists in Firestore without a later read.
