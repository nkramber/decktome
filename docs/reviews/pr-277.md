## Findings

### P2-1: The request cap is independent on each API instance

Status: open.

Open at: `a5583dfed06afdab3e0e7358132faa1889cd8505`.

File: `go/internal/agentsvc/fetch.go:47-50`.

Trigger: one user sends requests that Cloud Run routes to more than one API instance within a minute.

Expected: D-1100 limits each user to 10 Archidekt reads per minute.

Actual: `Server.New` creates a new in-memory `ratelimit.Limiter` for each process. Each instance permits 10 reads for the same user.

Consequence: a user can exceed the stated cap, and the service can send more requests to Archidekt than D-1100 permits.

Correction: enforce the per-user cap across API instances.

Regression check: send more than 10 reads for one user across two server instances in one minute. The combined requests must not exceed 10.

### P2-2: An import can claim a deck that it never read

Status: open.

Open at: `a5583dfed06afdab3e0e7358132faa1889cd8505`.

File: `go/internal/agentsvc/import.go:86-88`, `go/internal/agentsvc/fetch.go:63-74`.

Trigger: an authenticated client calls `ImportDeck` with any valid Archidekt deck URL and unrelated list text, without first calling `FetchDeckList`.

Expected: D-1101 defines `source_url` as the Archidekt deck that the import read. The server stores only the link that it made from that read.

Actual: `sourceURL` checks only that the client supplied an Archidekt deck URL, then stores its ID. `TestImportKeepsOnlyTheRemadeLink` confirms that `ImportDeck` accepts this URL without a preceding fetch.

Consequence: the saved deck and its public share can attribute unrelated list data to an Archidekt deck.

Correction: bind the stored source to a server-verified read for this user and import.

Regression check: reject a direct import with an unverified source URL, and accept a source returned by a successful read.
