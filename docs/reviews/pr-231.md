### P1-1: A delayed build can deploy after a newer build

Status: accepted risk, D-945.

Open at: `64a4891abcb38e211a3e516d6d3d536ee4652b2f`.

File: `cloudbuild/api.yaml:43-65`.

Trigger: Build A reads an older live commit and passes its guard. Build B then passes its guard and deploys. Build A can start its deploy step after B completes.

Expected: D-943 accepts a one-minute overlap. D-945 requires a build that deploys over a later commit to fail and name the build to run again.

Actual: The race can still replace the newer API or web deploy. The post-deploy order checks detect the later commit and fail the older build.

Consequence: The later build must run again to restore the API, web, and worker jobs. D-945 records this accepted recovery path.

Correction: Each API revision and Hosting release records its commit. Keep `api-order` and `web-order` after deploy, and fail with the newer commit when the race occurs.

Regression check: `test_two_builds_that_overlap` proves both guards can pass, the older build can deploy last, and both order checks fail with a rerun instruction. `BuildFilesTest` requires both checks in the Cloud Build files.
