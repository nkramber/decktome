## Findings

### P1-1: A delayed build can deploy after a newer build

Status: open.

Open at: `64a4891abcb38e211a3e516d6d3d536ee4652b2f`.

File: `cloudbuild/api.yaml:43-65`.

Trigger: Build A reads an older live commit and passes its guard. Build B then passes its guard and deploys. Build A can start its deploy step after B completes.

Expected: The PR-81 gate says an old build can not replace a newer one. D-943 also requires a build to skip its deploy when the live commit is later.

Actual: The guard reads the live commit in one step. A later step deploys the image without a lock or an atomic order check. The web build has the same gap between its guard and release.

Consequence: An older API or web build can replace the newer deployed version. The API build can also move the worker jobs back to older images.

Correction: Serialize the full deploy path, or use an atomic mechanism that blocks an older build after a newer one.

Regression check: Add a deterministic two-build test. Pause the older build after its guard, deploy the newer build, then prove the older build can not replace it. Cover the API, web, and worker job updates.
