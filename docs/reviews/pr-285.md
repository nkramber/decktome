## Findings

### P2-1: The guard allows changes to feedback storage and service paths

Status: open.

Open at: `dda60f3b4bf2577d0fcdc66850771b21207108bd`.

File: `go/cmd/live-evals/guard.go:15-52`.

Trigger: A reader note steers a live-eval session to change `go/internal/feedback/feedback.go`, `go/internal/feedbacksvc/`, or the feedback service contract.

Expected: Hold changes outside the deck-builder scope under D-1157. D-1158 uses the guard as the backstop for out-of-scope pull requests.

Actual: `protectedPrefixes` and `protectedFiles` do not cover these paths. `protectedOf` therefore returns no protected path, and the script can send a ready notice.

Consequence: A live-eval session can alter how the app stores or exposes feedback from users, then present that pull request as ready.

Correction: Protect the feedback storage, service, and contract paths. Add guard tests for each path.

Regression check: `go test ./cmd/live-evals`. Not run for this proposed correction.
