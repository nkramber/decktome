### P2-1: A slow failed snapshot run skips its alert

Status: fixed in `3673ca4ed961bd314d7e7fc41601f55e0d3d5c59`.

Open at: `44d2fb05e2f86cd22219f4c57361d8ab3b9b1ac8`.

File: `go/cmd/worker/main.go:92-93, 219-229`.

Trigger: A snapshot job starts in an alert window, then its refresh fails after that window. The worker allows a refresh to run for up to 90 minutes.

Expected: D-911 requires an alert for a failed job or a stale snapshot, with no more than four snapshot notices per day.

Actual: The old code called `snapshotNotice` after `runOnce` returned and checked the end time. The correction records the start time and uses it for the alert window. The notice age still uses the end time.

Consequence: The old code can leave the snapshot stale without an alert for the owner.

Correction: `run` records the UTC start time and passes it to `snapshotNotice`. The test verifies a run that starts at 18:00:05 and fails at 18:40:05 still sends a notice, while a run outside the window sends none.

Regression check: `go -C go test ./cmd/worker -run 'Test(SnapshotNotice|ASlowFailedRunStillAlerts)$' -count=1`: passed. `TestASlowFailedRunStillAlerts` asserts the end-time age and error in the notice. The prior behavior failed with `sent false`.
