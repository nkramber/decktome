## Findings

### P2-1: A slow failed snapshot run skips its alert

Status: open.

Open at: `44d2fb05e2f86cd22219f4c57361d8ab3b9b1ac8`.

File: `go/cmd/worker/main.go:92-93, 219-228`.

Trigger: A snapshot job starts in an alert window, then its refresh fails after that window. The worker allows a refresh to run for up to 90 minutes.

Expected: D-911 requires an alert for a failed job or a stale snapshot, with no more than four snapshot notices per day.

Actual: `run` calls `snapshotNotice` after `runOnce` returns. `snapshotNotice` checks the current hour and minute. A failed run that ends at 06:16, for example, fails the `minute < 15` condition and sends no notice.

Consequence: A failed refresh can leave the snapshot stale without an alert for the owner.

Correction: Preserve the eligible scheduled window from the start of the run, then use it when the refresh result is known.

Regression check: Add a test where an eligible run starts at 06:00 and fails after 06:15. Require one notice. No such test exists at this head.
