## Findings

### P2-1: A later marker can strand an earlier failed marker

Status: open.

Open at: `1ccaf429161ef45d8d895e43002b08c1e5db06e1`.

File: `go/internal/cards/newcards.go:125-132`.

Trigger: A pass for version v1 stops after a partial scan. A later snapshot writes a v2 marker, and its pass completes.

Expected: Process every pending marker in order. The PR-120 roadmap says a failed or stopped pass runs again, and each pass sends one push (`docs/design-roadmap.md`, D-1091).

Actual: `LatestNewCards` returns only the newest marker. `newCardsPass` then exits when that marker has a `Pass` value. The pending v1 marker never runs.

Consequence: Decks that only fit v1 cards miss that panel and push. The v2 pass can also clear cards that v1 wrote before it stopped.

Correction: Select the oldest pending marker and process pending markers in order. Add a worker regression test with pending v1 and completed v2 markers.

Regression check: The new test must prove that v1 runs after v2 exists and that v2 does not make v1 disappear. No such test exists at this head.
