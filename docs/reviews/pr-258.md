## Findings

### P2-1: Sign-out skips push cleanup when local storage fails

Status: open.

Open at: `2089b508b1415ff22757aeaf4569b8ef17ebba36`.

File: `web/apps/web/src/features/push/push.ts:159-162`.

Trigger: the browser registers a device with the API, then `localStorage.setItem` fails while `writeFlag(true)` stores consent. On sign-out, `readFlag()` returns false.

Expected: sign-out removes the device and ends its Cloud Messaging registration (D-1005).

Actual: `releasePushOnSignOut` returns before `disablePush`. The API still stores the device, and the browser keeps its Cloud Messaging registration.

Consequence: the signed-out browser can receive the previous account's deck name and link. A later account does not need to opt in for this stale registration to remain active.

Correction: do not use the local storage flag as the precondition for sign-out cleanup. Add a regression test that makes local storage fail after registration and checks API removal and Cloud Messaging cleanup.

Regression check: the storage-failure sign-out test is absent. Run it with the push tests after correction.
