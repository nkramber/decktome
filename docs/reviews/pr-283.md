## Findings

### P2-1: The classifier drops hard avoidance

Status: open.

Open at: `d1c6ce5947462369809af9e764fac01df05be94e`.

File: `go/internal/questions/prompts.go:104`.

Trigger: A user asks for "no artifacts". The classifier instruction says to write only the thing and omit "no". The state therefore stores `artifacts` in `Slots.avoid`.

Expected: The roadmap says a hard request such as "no artifacts" ranks each artifact lower. The `avoidMatch` hard branch must receive the negation to select every card of that type.

Actual: With only `artifacts`, `avoidMatch` treats the word as the `artifacts` row. It keeps payoff signals and does not add the Artifact type signal. Artifacts without an artifact payoff, such as Swiftfoot Boots, do not receive the penalty. The unit test passes "no artifacts" directly to the matcher, so it does not test the classifier-to-builder path.

Consequence: The app does not honor a hard type avoidance request through normal chat.

Correction: Preserve hard versus soft avoidance in the classifier output or in a separate field. Add a test from classifier output through candidate ranking for both "less artifacts" and "no artifacts".

Regression check: `go test ./internal/questions ./internal/candidates` passed, but it does not test this path. The correction must make that end-to-end case pass.
