## Findings

### P2-1: Cold token and invite reads can exceed the seven-second limit

Status: fixed in `d2c0e00b069c1976de15511a26ea98b2c50468b5`.

Open at: `f7f4f7ed681b9964ee7cbe40c0f396d4bab256a3`.

File: `go/internal/authblock/authblock.go:45-46`.

Trigger: A cold instance fetches the certificate key, then reads an expired or empty invite-list cache. The certificate client can wait 3 seconds (`go/cmd/api/main.go:270`), and `allowTimeout` permits another 5 seconds (`go/internal/authblock/authblock.go:118`).

Expected: The handler must complete within Identity Platform's seven-second limit (D-990, `docs/setup-gcp.md`, section 15.1).

Actual: The two bounded waits allow 8 seconds before other handler work.

Consequence: Identity Platform fails a valid invited sign-up when both reads take their allowed time.

Correction: Apply one overall deadline below seven seconds to token-key retrieval and the invite-list read. Keep enough time to write the response.

Regression check: `go test ./internal/authblock/ ./cmd/api/` passed. `TestOneDeadlineBoundsTheKeyAndTheList` verifies that one five-second budget bounds both reads.

### P2-2: The Gitar gate accepts a dashboard that says a review is in progress

Status: open.

File: `docs/tools/codex_review.py:203-204`.

Correction: Make the gate detect the documented in-progress text as well as the spinner image. Add a regression test for a text-only status line.

Regression check: The direct reproduction returned `[]` on this head. Add the text-only case to `docs/tools/test_codex_review.py` and verify that it fails before the correction and passes after it.
