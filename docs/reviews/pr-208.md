## Findings

### P2-1: The docs-only push path has no previous head

Status: open.

File: `.github/workflows/verify.yml:74`.

Trigger: Push a docs-only commit to a pull request whose earlier commits changed code.

Expected: D-805 says the code jobs skip when the previous `verify:gate` passed and `main` has no intervening code change.

Actual: The `pull_request` workflow reads `github.event.before`. GitHub documents `before` on push payloads. The `pull_request` payload has `action`, `number`, and `pull_request`, but no `before` field ([GitHub webhook payloads](https://docs.github.com/en/webhooks/webhook-events-and-payloads)). On `synchronize`, `BEFORE_SHA` is empty, so the workflow exits before it writes push paths. `changed_paths.py` then sees the full pull-request paths, finds the earlier code path, and runs all seven code jobs again. Run `35796631196` reproduced this on review commit `95eabbb`: its docs-only push started all seven code jobs.

Consequence: Every docs-only push to a code pull request repeats the seven code jobs. The feature in D-805 does not work for this supported case.

Correction: Obtain the prior head from a source available to the `pull_request` event, then pass it to the existing checks and base-path logic.

Regression check: Add an integration check for a `synchronize` payload with no top-level `before`. Prove that a docs-only push skips only when the prior `verify:gate` passed and `main` has no code changes since that head.
