## Findings

### P2-1: The parser silently drops lines after line 1000

Status: open.

Open at: `a32ac85c486ca9c6ff9058a2abd9700259ea29af`.

File: `go/internal/decklist/decklist.go:81-85`.

Trigger: Submit a list within the 128 KiB request limit that has 1001 valid card lines.

Expected: Report every skipped line or reject the whole list. D-23 says an import must not silently drop input. D-846 also requires the import to report unresolved names.

Actual: `Parse` stops when it reads line 1001 and returns the first 1000 lines without an error. `ImportDeck` then resolves and stores that partial list as a successful deck and session.

Consequence: The saved deck omits a card from the submitted list, and its validation describes different data from the user's input.

Correction: Return an explicit limit error when the parser reaches a line beyond `maxLines`. Do not store a partial deck.

Regression check: Add a parser or import test with 1001 valid card lines. Require an explicit error and prove that the import stores no deck.
