## Findings

### P2-1: A hidden mount never reports that the page is hidden

Status: open.

Open at: `673c86f546c0300072e579097618b42f96fcbd8b`.

File: `web/apps/web/src/features/chat/use-page-hidden.ts:16-22`.

Trigger: Mount `usePageHidden` for an active build while `document.visibilityState` is already `hidden`, with no earlier presence record for this page.

Expected: D-1033 requires the page to tell the server when it goes to the background. The server must know that the page stays in the background when it stores the deck.

Actual: The hook sets `reported` to `true` but sends no request on mount. It sends only after a later visibility change. The server therefore reads no presence record, and `pageLeft` returns false while the stream remains open.

Consequence: A page that mounts hidden during a build can miss the push when the server stores the deck, despite remaining hidden.

Correction: Report the initial hidden state to the API when the active hook mounts hidden. Add a regression test that asserts the initial `hidden:true` report and the later `hidden:false` report.

Regression check: No focused test covers this mount state. The existing `session-page.test.tsx` case covers a later return report only. `make verify` passes on this head, but does not falsify this behavior.
