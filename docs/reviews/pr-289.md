## Findings

### P1-1: The setup does not protect the copied credentials

Status: fixed in `9e1982441a50b10874fa1fe159a28fc090d37cad`.

Open at: `96cb6ae0301b07f656b5cf34a8a2499e90272988`.

File: `scripts/live-evals.sh:68-71` at the finding head.

Trigger: Create a credential file under umask `022`.

Expected: The setup creates private credential files. D-1141 and D-1164 require that another account can not read them.

Actual: At the finding head, shell redirection created mode `644`. The new `umask 077` and mode checks reject group and other permission bits.

Consequence: The old setup can expose the owner's GitHub token and Claude token to another local account.

Correction: The current setup uses `umask 077`. The script and installer reject group or other mode bits.

Regression check: The author response reports that mode `644` now fails and mode `600` passes. This review also verified the corrected mode-bit expression and found the separate ACL case in P1-2.

### P1-2: The credential check ignores read access control lists

Status: open.

Open at: `9e1982441a50b10874fa1fe159a28fc090d37cad`.

File: `scripts/live-evals.sh:258-261` and `scripts/live-evals-launchd.sh:61-63`.

Trigger: Give a mode `600` credential file an ACL entry `everyone allow read`.

Expected: The script and installer reject any credential file that another account can read. D-1141 and D-1164.

Actual: Both checks inspect only the POSIX mode bits. On this Mac, `chmod +a 'everyone allow read'` left `stat -f %Lp` at `600`. The check passed while `ls -le` showed the ACL grant.

Consequence: Another local account can read the copied owner GitHub token, which can access the owner's repositories.

Correction: Reject ACL entries that grant read access to another account, or remove such entries before the checks.

Regression check: Give a mode `600` file an ACL that grants `everyone` read access. Verify that both checks reject it. Also verify that a mode `600` file with no such ACL passes.

### P2-1: The version gate does not pin jq

Status: open.

Open at: `9e1982441a50b10874fa1fe159a28fc090d37cad`.

File: `scripts/live-evals.sh:165-184`.

Trigger: Update `jq` while the other pinned versions stay unchanged.

Expected: A tick checks the version of each program that reads or writes the removable-volume state. D-1165.

Actual: The preflight requires `jq`, but `PINS` has no `jq` entry. Later calls use it to read and write files under `$STATE` at lines 326, 343, and 347.

Consequence: A changed `jq` can access the state without a pin check, so the tick does not stop and notify the owner as D-1165 requires.

Correction: Add a `jq` version check to `PINS` and test that a mismatched version stops the tick before the build.

Regression check: Change the reported `jq` version in a controlled test. Verify that the tick records and sends one notice, then sends no repeat notice.
