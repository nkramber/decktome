## Findings

### P1-1: The setup does not protect the copied credentials

Status: open.

Open at: `96cb6ae0301b07f656b5cf34a8a2499e90272988`.

File: `scripts/live-evals.sh:68-71`.

Trigger: Run the two redirection commands under the normal macOS umask of `022`.

Expected: The setup creates each credential file with mode `600`, as its instruction requires. D-1141 isolates the session logins, and D-1164 copies the owner's GitHub and Codex logins.

Actual: Shell redirection creates a new file with mode `644` under umask `022`. A local reproduction created `gh-token` with mode `644`. The preflight and token reads check that files exist, but they do not check their modes.

Consequence: Another local account can read the copied GitHub token and the Claude token. The GitHub token reaches every repository of the owner.

Correction: Set a restrictive umask or run `chmod 600` in the setup, then reject credential files with broader permissions before the script uses them.

Regression check: Under umask `022`, verify that setup creates each credential file with mode `600`. Verify that preflight rejects a file with mode `644`.
