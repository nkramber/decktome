## Findings

### P2-1: A stopped reading turn is described as a deck build

Status: fixed in `711fd3e5a6fa45facf2c24bb9f5d35557cb00fd2`.

Open at: `3ccc9174133814e6839e5d91ffb09be954a2b887`.

File: `web/apps/web/src/features/chat/session-page.tsx:630-633`.

Trigger: The user presses Stop while a first turn is in `READING`. `onStop` starts the server watch and marks the turn stopped. The server still reads `READING`, so `serverReply` is true.

Expected: The status line describes the work that the server still does, as D-375 requires. A reading turn can return questions, so its line must not promise a deck.

Actual: The stopped-state line always says that a build continues and a deck will appear. It does not check `serverReply`.

Consequence: The user sees a deck promise when the server instead returns questions.

Correction: Select the stopped-state line from the server phase. Keep the deck message for a build, and use a reply message while the phase is `READING`.

Regression check: Add a UI test that stops a first turn during `READING`. Check that the line describes a pending reply and makes no promise of a deck. Run the focused web test and `make verify` with Node 22.
