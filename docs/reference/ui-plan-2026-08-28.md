## 3. The user path

Each step names the screen, the RPC it calls, and what the user sees.

1. Sign-in. An email and password form over the Auth emulator. A new user signs up on the same form. The ID token goes in the `Authorization` header of every RPC (D-268).
2. Collection. Upload a ManaBox CSV, or skip. `CollectionService.ImportCollection` returns the counts, and the screen shows them with the unresolved rows. `ListCollections` shows earlier uploads. Skip goes to the chat in any-card mode (D-37).
3. Chat. One text box and a thread. `AgentService.Chat` streams. The thread shows each event. A question shows its options as buttons and a free-text field. The prose, a status line, a failure, and the usage total (M-1) each get a line. An option click sends an `Answer` with `option_index`. Free text sends `text`.
4. Deck. The `deck` event opens the deck view beside the thread. Cards group by role. Each card shows its art, the artist, and the copyright line (D-6). A double-faced card shows both faces (F-9). The view marks an owned card, and a card to buy shows its price. The view shows the findings, `legality_as_of`, the mana curve, and the color sources. Hover or tap shows the Oracle text.
5. Export. A button copies the deck as Arena text and downloads it as a file. A buy list shows the cards the user does not own, with a Scryfall link each (D-15).

## 4. Contract changes

The contract needs two additions. Both are additive, and `buf breaking` passes.

- `CardService.GetCards(oracle_ids)` returns up to 120 cards in one call. The deck view needs the art, the type line, the mana cost, and the faces of every card. `DeckCard` carries only the id and the name. One `Lookup` per card is 100 calls per deck.
- `DeckService.ExportDeck(deck_id, format)` returns the text and a file name. The first format is `EXPORT_FORMAT_ARENA_TEXT`, which ManaBox imports. The Export RPC left the contract on 2026-08-28 because nothing implemented it (D-266). This one lands with its implementation.

The export text is one card per line: the count, the name, then the set code and the collector number of the default printing. The commander goes first under a `Commander` header, and the sideboard under a `Sideboard` header. `collections.ParseArenaText` reads that shape already, so the round-trip gate of PR-13 runs against our own parser. ManaBox states that the set and the number are optional and that the Arena shape is its standard (manabox.app guide, read 2026-08-28).

Nothing else changes. `Chat` streams every event the UI needs. The mana curve and the color sources come from the card data on the client.

## 5. The web architecture

The app stays one Vite app in `web/apps/web`. The generated client stays in `web/packages/api-client`.

- State in three tiers (wallabee pattern). TanStack Query holds server state: collections, decks, cards. Zustand holds client state: the session id, the collection id, the pool mode. React context holds the auth user.
- Streaming. The Connect client returns the `Chat` stream as an async iterable. One hook reads it, appends events to the thread, and stops on `failure` or `deck`. An `AbortController` cancels it on unmount.
- Auth. The `firebase/auth` web SDK, with `connectAuthEmulator` to `127.0.0.1:9199` in local mode. A Connect interceptor adds the bearer token. The API accepts it through the emulator path (D-268).
- Routes. `react-router` with four routes: `/sign-in`, `/collection`, `/session/:id`, and `/decks`. The session id also sits in `localStorage`, so a reload returns to the chat.
- Style. Tailwind 4 and no component library in this pass.
- Boundaries. One ESLint rule per feature folder with an allowlist of the features it can import, as wallabee-ui does. The features are `auth`, `collection`, `chat`, `deck`, and `export`.
- Images. Every `img` has the artist and the copyright in the DOM, and no CSS crops it (D-6, guardrail 7).

## 7. The live test, step by step

1. Put the provider keys in `.env`.
2. Run `make dev`. Wait for the snapshot to load: `curl localhost:8090/readyz` answers 200.
3. Open `http://localhost:5180`. Sign up with any email and password. The emulator accepts them.
4. Upload `go/internal/collections/testdata/manabox_collection.csv`, or the owner's own export. Read the count.
5. Ask for a deck. Answer the questions. Read the deck.
6. Export. Import the file into ManaBox on a phone. Compare the count.

## 8. Risks and open questions

- Scryfall image links. D-6 allows the hotlink, and Scryfall asks for no more than ten requests per second. A deck view loads about 100 images at once from the Scryfall CDN, which is the intended use. If the CDN refuses, the view falls back to the small images.
- A session has no list RPC. The chat resumes from the id in `localStorage`. A user who clears the browser loses the session. A `ListSessions` RPC is a later addition if the owner wants it.
- `Answer.option_index` is optional now (D-266). The client sends it only on a button click.
- The Auth emulator forgets its users on restart unless `make dev` exports them. `scripts/dev.sh` exports Firestore, and the plan adds the auth export to the same flag.
- The classify prompt reads `prior_messages`, so a long chat grows the input. The 8 KiB message cap holds one message, not the thread. The plan caps the thread the UI sends at the last five messages, which is what the agent reads.
